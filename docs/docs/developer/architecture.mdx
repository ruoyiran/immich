# Architecture

This repository contains the Immich Web and Mobile clients, generated API clients, a committed OpenAPI contract snapshot, and browser UI tests.

The server implementation is maintained in the sibling `photo-classifier` repository. It provides the Go/Gin API, MySQL persistence, media upload and delivery, background job orchestration, the Rust processing pipeline, and deployment configuration.

## Runtime topology

```text
Web (SvelteKit) ─┐
                 ├─ HTTP / WebSocket ─> photo-classifier Go API ─> MySQL and media storage
Mobile (Flutter) ┘                                  │
                                                    └─> Rust pipeline and external model services
```

The legacy `machine-learning/` package remains available as an independently buildable service, but it is not part of the current `photo-classifier` runtime.

## API contract

The server implementation is the source of runtime behavior. This repository commits `open-api/immich-openapi-specs.json` as the client-generation input. The snapshot generates:

- the TypeScript SDK in `packages/sdk/`;
- the Dart client in `mobile/generated/openapi/`.

Server changes must be implemented and tested in `photo-classifier` before updating the snapshot and regenerating clients with `mise //:open-api`.

## Development connections

The Web development proxy uses `IMMICH_SERVER_URL` and defaults to `http://127.0.0.1:8080`, the default `photo-classifier` server address. Mobile users configure the server endpoint in the app.
