# Day-Bucketed Similar Photo Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Detect highly similar photos only within the same capture-location calendar day, expose conservative duplicate groups through the existing Immich duplicate API, and add a safe Mobile review flow that moves confirmed photos to trash.

**Architecture:** Upgrade the existing Rust similarity pipeline from pair-only v3 to day-bucketed v4, preserving CLIP+pHash scoring while generating conservative complete-link groups. The Go compatibility server exposes the already-generated official `/duplicates` contract and reuses the existing logical-trash, sync, and realtime paths. Flutter consumes the existing generated `DuplicatesApi` through a repository/provider/page flow and gates the Library entry on `duplicateDetection`.

**Tech Stack:** Rust/MySQL pipeline, Go/Gin compatibility API, Flutter/Dart/Riverpod/AutoRoute, generated Immich OpenAPI SDK.

**Spec:** `docs/superpowers/specs/2026-09-06-day-bucketed-similar-photo-cleanup-design.md`

## Global Constraints

- `capture_day` is the capture-location natural day: `DATE(taken_at)` using the stored wall-clock value.
- Photos from different natural days are never compared.
- Similarity remains `0.85 × CLIP + 0.15 × pHash`, with a strict `> 0.90` final threshold.
- Every active group is disjoint and complete-link: every member pair must satisfy the threshold.
- The feature never automatically trashes or permanently deletes assets.
- Mobile confirmation performs logical trash only; permanent deletion remains a separate trash workflow.
- The Rust pipeline remains the only writer of generated similarity scans.
- Database DDL originates in `../photo-classifier/pipeline-rs`; mirror it in Go test schema and architecture docs.
- Do not modify `mobile/generated/openapi/` or `packages/sdk/src/fetch-client.ts`; the required duplicate contract already exists.
- Do not create commits unless the user explicitly authorizes them. Each task ends with a review checkpoint and an optional suggested commit.
- This is internal cross-repository work. Do not open an upstream Immich PR generated by an LLM.
